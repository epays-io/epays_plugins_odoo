ePays Payment Provider

Cards, Benefit, BenefitPay, Apple Pay, Google Pay, Samsung Pay and Tabby through the ePays hosted payment page

Let your customers pay on the ePays payment page from the Odoo shop, the customer portal and payment links. Odoo checks every result with ePays, server to server, and completes the order the standard way: the sales order is confirmed, the payment is posted in accounting and the invoice is reconciled.

  • Hosted redirect: no card data ever touches your Odoo server.
  • Visa and Mastercard cards, Benefit, BenefitPay, Apple Pay, Google Pay, Samsung Pay and Tabby, as enabled on your ePays account.
  • One "ePays" option showing every logo, plus individual methods that open their gateway directly.
  • Production and Sandbox modes, with separate sandbox credentials; Test state is visible only to your staff.
  • A connection test that tells you exactly what to register with ePays.
  • Order references in the ePays custom fields, for easy reconciliation.
  • A scheduled check for customers who close the browser after paying.
  • English and Arabic.
ePays is an external, paid service: you need an ePays merchant account.

Installation

A payment provider contains Python code, so Odoo installs it only from the server's addons_path; Apps > Import Module cannot install it.

  • On-premise: unzip the payment_epays folder into a directory of your addons_path, restart Odoo, then Apps > Update Apps List and install ePays Payment Provider.
  • Odoo.sh: add the module to your project repository, or use the Deploy on Odoo.sh button of this page, then install it from Apps.
  • Odoo Online (SaaS) is not supported: it cannot run third-party Python modules.

The provider is created Disabled, so nothing changes at checkout until you configure it as described below. Behind a reverse proxy, run Odoo with proxy_mode = True.

How to use it

1. Get your ePays details

Ask ePays for:

  • your merchant API ID and API master key, and a sandbox pair if ePays gives you one;
  • your licence to list your shop domain (for example shop.example.com) and the public IP address of your Odoo server;
  • the gateways you want (cards, Benefit, BenefitPay, Apple Pay, Google Pay, Samsung Pay, Tabby) activated on your account.
2. Enter the keys

As an administrator, open Invoicing (or Website) > Configuration > Payment Providers > ePays, then the Credentials tab:

  • API ID and API Master Key: your production keys.
  • Sandbox API ID and Sandbox API Master Key: your test keys. Leave them empty to use the production keys for tests too.
  • Merchant Domain: the domain on your ePays licence. Leave it empty to use your website's domain.
  • Mode: the ePays server that takes the payments.
ModeServerUse it for
Productionapi.epays.ioReal payments. Required when the provider is Enabled.
Sandboxtestapi.epays.ioTest payments, with the sandbox keys.

Click Find this server's IP address to get the public IP address to give ePays, with a copy button. Then click Test connection: it either confirms that the connection works or says what to fix: a wrong key, a domain missing from your licence, or the exact IP address to ask ePays to register.

3. Choose the payment methods

ePays is on by default: one option at checkout, showing every logo, where the customer picks the method on the ePays page. To offer Card, Benefit, BenefitPay, Apple Pay, Google Pay, Samsung Pay or Tabby as separate options, turn them on with Enable Payment Methods, then click Sync from ePays in the Configuration tab so each one opens its gateway directly.

4. Test on your live shop

Set the state to Test. The mode switches to Sandbox, and only logged-in staff see ePays at checkout; customers see nothing. Click Sync from ePays, place an order in BHD, pay on the ePays test page and check that the order is confirmed.

5. Go live

Set the state to Enabled. The mode switches to Production and ePays is shown to every customer. Click Test connection and Sync from ePays again, since the production server has its own gateways. To stop taking ePays payments, set the state to Disabled: your keys and settings are kept, and payments already in progress still complete.

6. Every day
  • Shop: the customer picks ePays, pays on the ePays page and comes back to the order confirmation. The sales order is confirmed and the payment is posted in the provider's journal.
  • Quotations, invoices and payment links: customers can also pay from the customer portal, or from a link made with Generate a Payment Link on a sales order or invoice.
  • Payment details: each paid order and invoice gets an internal note with the ePays payment id, the gateway reference and the masked card. The same details are on the payment transaction.
  • Customer closed the browser after paying: the scheduled action ePays: check pending payments completes the order within 15 minutes. Keep it active.
  • Customer goes back and pays again: the same ePays payment is reused, so an order never has two payable links.
  • Reconciliation: in the ePays portal, find a payment by its sales order number (udf2) or invoice number (udf3).
7. Find a payment in Odoo

Every attempt to pay is a payment transaction. Odoo lists them in developer mode only: activate it first (Settings > Developer Tools > Activate the developer mode).

  • All ePays payments: Invoicing (or Accounting) > Configuration > Online Payments > Payment Transactions, or Website > Configuration > eCommerce > Payment Transactions. Filter or group by provider ePays; search the Provider Reference for an ePays payment id.
  • One transaction: its state and the message the customer saw, and an ePays section with the environment, the sales order and invoice numbers sent, the ePays transaction id, the gateway reference, the response code and description, and the gateway response (masked card, authorisation code, 3-D Secure result).
  • From an order or an invoice: each finished payment writes an ePays payment details note in its chatter, and the payment recorded in accounting links to its transaction.
ePays takes payments in Bahraini dinar (BHD). An order in another currency is converted to BHD with Odoo's exchange rate of the day, and the customer pays the BHD amount on the ePays page; the payment is recorded in the order's currency. Keep your exchange rates up to date: ePays is not offered in a currency Odoo has no rate for.

Payment methods at checkout

  • ePays, on by default: one option showing the logos of every method. The customer chooses the method on the ePays page.
  • Card, Benefit, BenefitPay, Apple Pay, Google Pay, Samsung Pay, Tabby, off by default: each one opens its ePays gateway directly. Turn them on in the provider's payment methods.

Click Sync from ePays on the provider to read the gateways activated on your merchant account; each is linked to its payment method automatically, and you can correct a link. Benefit and BenefitPay are offered when the billing address selected at checkout is in Bahrain; Tabby when it is in Bahrain, Saudi Arabia, the UAE or Kuwait; Apple Pay only on browsers that support it. All payment method logos are ePays artwork, and other payment providers are not affected.

Reconciliation

Every payment carries the order and invoice numbers in two ePays custom fields:

FieldValueExample
udf2Sales order number(s)S00012
udf3Invoice number(s), for portal and payment-link invoice paymentsINV/2026/00012

Going back and paying the same order again reuses the same ePays payment while it is pending, so an order never has two payable ePays links. If the cart changed, or the customer chose another payment method, the old payment is voided first and a new one opens for the chosen method.

udf6 to udf10 are never sent: ePays uses them as gateway settings (for example the MPGS merchant ID and the Benefit alias). When a payment completes, Odoo checks that ePays returns the same order and invoice numbers.

When a payment finishes, the ePays payment id, transaction id, gateway reference, response and the masked card details are shown on the Odoo transaction and written as an internal note on the sales order and invoice.

Data shared with ePays

For each payment, Odoo sends ePays:

  • the amount, in BHD (converted when the order is in another currency);
  • the sales order and invoice numbers (udf2 and udf3);
  • the database and website names and the Odoo and addon versions, in the request's User-Agent;
  • optionally (on by default, can be switched off), the customer's name, email, phone and address.

Odoo receives from ePays the payment result, including masked card data (last four digits) and authorisation details, and stores them on the transaction.
